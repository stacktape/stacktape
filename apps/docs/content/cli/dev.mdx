# dev

The `stacktape dev` command runs containers, frontends and supported database emulators on your machine. Lambda functions and Batch jobs run in AWS. Dev mode injects connection settings and credentials into workloads and streams their logs while you iterate on code.

## Usage

```bash
stacktape dev --stage dev-john --region eu-west-1
```

## What it does

The `dev` command deploys a dev stack to AWS. It includes Lambda functions, Batch jobs and configured cloud resources allowed by the dev deployment policy, such as gateways, queues, topics and buckets. Selecting workloads does not limit all cloud resources to their dependencies. The dev stack has no alarms: errors you cause on purpose while developing do not notify anyone.

- Runs containers and frontend workloads locally; Lambda functions and Batch jobs execute in AWS
- Emulates databases (PostgreSQL, MySQL, MariaDB, DynamoDB, OpenSearch) and Redis locally using Docker
- Keeps local databases on your machine, published on `127.0.0.1` only; deployed Lambda functions and Batch jobs reach them through the [dev network](/local-development/debugging-lambda-functions#the-dev-network). Use `--remote-resources` for deployed database connections
- Creates the dev stack automatically on first run — no pre-deployment required
- Injects environment variables, secrets, and AWS credentials into local workloads

## Supported resource types

The `dev` command can run the following resource types locally:

| Category | Resource types |
|----------|---------------|
| Containers | web-service, private-service, worker-service, multi-container-workload |
| Frontends | nextjs-web, astro-web, nuxt-web, sveltekit-web, solidstart-web, tanstack-web, remix-web, hosting-bucket (with `dev` config) |
| Databases (locally emulated by default) | PostgreSQL, MySQL, MariaDB, DynamoDB, Redis, OpenSearch |

## Important flags

### --resources / --skip-resources

Select Lambda functions, local containers, frontends and emulated databases. Without these flags, an interactive picker appears. Unselected functions remain in the dev stack with their configured triggers removed. Batch jobs cannot be selected or skipped: they run in AWS when triggered, and their images update only when dev mode starts. Use a dev-specific configuration to omit a job or disable its triggers.

Run all resources without prompting:

```bash
stacktape dev --stage dev --region eu-west-1 --resources all
```

Run only specific resources:

```bash
stacktape dev --stage dev --region eu-west-1 --resources myApi,myDb
```

Run everything except a heavy database:

```bash
stacktape dev --stage dev --region eu-west-1 --skip-resources myHeavyDb
```

### --watch

Enables automatic file watching. When source files change, Stacktape automatically re-executes the affected compute resource.

```bash
stacktape dev --stage dev --region eu-west-1 --watch
```

### --remote-resources

Databases and Redis run locally by default. Use `--remote-resources` to connect selected resources to deployed AWS resources instead. This is useful when you need to test against real data or when local emulation is insufficient.

```bash
stacktape dev --stage dev --region eu-west-1 --remote-resources myPostgres
```

### --fresh-db

Deletes data, schema and local credential/identity files for databases prepared during startup, including deployed-workload relay dependencies that may be unselected. Other persisted databases are untouched. DynamoDB Local shares storage across tables, so resetting it removes every persisted table in that storage. See [reset scope](/local-development/local-databases#resetting-local-data).

```bash
stacktape dev --stage dev --region eu-west-1 --fresh-db
```

### --no-tunnel

Skips the tunnels from deployed Lambda functions to local databases. Without it, functions that use a local database reach it through the dev box of your account's dev network; see [Connecting to local databases](/local-development/debugging-lambda-functions#connecting-to-local-databases). VPC functions still run in the dev network.

```bash
stacktape dev --stage dev --region eu-west-1 --no-tunnel
```

### --take-over

Moves a stage that another `stacktape dev` session runs, on another machine or in another worktree, to this session. Without it, `stacktape dev` refuses to start a stage whose deployed functions already reach another session's databases, and names that session. With it, the functions reach the databases on this machine, their open database connections to the other session are closed, and the other session stops itself with a message that names this one, so it cannot redeploy functions over yours.

```bash
stacktape dev --stage dev --region eu-west-1 --take-over
```

### --no-emulation

`--no-emulation` affects selected local directive-resolution behavior. Dev mode still deploys its AWS dev stack and uses the normal container role-credential and connection-variable paths. This flag does not make dev mode offline or suppress credential injection.

```bash
stacktape dev --stage dev --region eu-west-1 --no-emulation
```

### --agent / --agent-port

The `--agent` flag runs dev mode as a detached daemon and enables the agent HTTP server for programmatic control. Agent mode is intended for programmatic/LLM consumption and AI coding-agent workflows. The daemon spawns in the background and the parent process exits after confirming the agent is ready.

```bash
stacktape dev --stage dev --region eu-west-1 --agent
```

Providing `--agent-port` also enables agent mode, so `--agent` is optional when you pass a port. Use `--agent-port` to specify a custom port for the agent HTTP server:

```bash
stacktape dev --stage dev --region eu-west-1 --agent-port 8080
```

Stop a running agent with [`dev stop`](/cli/dev-stop).

## Interactive commands

While running in interactive mode, you can control dev mode with the following text commands:

| Command | Action |
|---------|--------|
| `rs` | Rebuild all workloads |
| `rs <name>` | Rebuild a specific workload by name |
| `q` or `quit` | Stop dev mode and exit |
| `c` or `clear` | Clear the log output |

## Examples

Basic dev mode with file watching:

```bash
stacktape dev --stage dev-john --region eu-west-1 --watch
```

Run only the API function and database, skip everything else:

```bash
stacktape dev --stage dev --region eu-west-1 --resources myApi,myDatabase
```

Run locally but connect to a deployed database instead of emulating it:

```bash
stacktape dev --stage dev --region eu-west-1 --remote-resources myDatabase
```

Start a dev agent for AI coding assistant integration:

```bash
stacktape dev --stage dev --region eu-west-1 --agent --resources all
```

Start with a fresh database (deletes existing local data):

```bash
stacktape dev --stage dev --region eu-west-1 --fresh-db
```

## FAQ

### Does `stacktape dev` require Docker?

Dev mode uses Docker to emulate databases (PostgreSQL, MySQL, MariaDB, DynamoDB, OpenSearch) and Redis locally. You need Docker installed and running for local database emulation. If you use `--remote-resources` for all databases, Docker is not required for database emulation, though container workloads may still use it for local builds.

### When should I use `stacktape dev` vs `stacktape deploy`?

Use [`stacktape dev`](/cli/dev) for iterating on code locally with fast feedback loops — it runs workloads on your machine and emulates databases without a full deployment cycle. Use [`stacktape deploy`](/cli/deploy) when you need to ship to AWS, test in a real cloud environment, or validate production behavior. Dev mode is for development; deploy is for staging, production, or integration testing.

### How can I connect to a real deployed database instead of the local one?

Use `--remote-resources` with a comma-separated list of resource names (for example `--remote-resources myPostgres,myRedis`). Databases and Redis run locally by default; this flag points the selected ones at their deployed AWS counterparts when local emulation is insufficient or you need to test against real data.

### What is agent mode and when should I use it?

Agent mode (`--agent`) runs dev mode as a detached daemon with an HTTP server for programmatic control. It uses JSONL output and disables the interactive terminal UI. Use agent mode when integrating with AI coding agents, automation tools, or any workflow that needs to control dev mode programmatically. Stop a running agent with [`dev stop`](/cli/dev-stop).

### Why does `stacktape dev` stop with "Free Plan Limit Reached"?

Dev mode deploys and updates a dev stack in your AWS account, so it follows the same
[Free plan cost limit](/stacktape-console/billing-and-subscription#free-plan-cost-limit) as
[`stacktape deploy`](/cli/deploy#free-plan-cost-limit). When a Free organization's managed AWS costs this month are
above $100, dev mode stops before it creates or deploys anything and prints the costs and the upgrade link. Upgrading
to the Flexible plan lifts the limit immediately. Running infrastructure is not affected, and
[`dev stop`](/cli/dev-stop) and [`delete`](/cli/delete) keep working.
