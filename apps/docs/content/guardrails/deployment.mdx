# Deployment guardrails

These guardrails decide where and how your team can deploy: which stages and regions, which commands, and whether
public endpoints must use your own domain. They appear under **Deployment restrictions** on **Security → Guardrails**.
[Guardrails overview](/guardrails/overview) explains who they bind and how to set them up.

## Stage restriction

Commands may target only the stage names you list, such as `production`, `staging`, `dev`. A deploy, delete or any
other guarded command for a stage that isn't listed stops:

```text
Blocked by the organization guardrail "Stage restriction". Stage `pr-42` is not allowed. Allowed stages: `production`,
`staging`.
```

The rule compares the exact stage name. Use it to keep stage names to a convention. It doesn't check what was deployed
to another stage first, so it can't require a staging deploy before production; put that order in your
[CI pipeline](/ci-cd-and-gitops/custom-ci-cd). Pull request previews (`pr-<number>`) can't be listed one by one, so an
organization that uses previews usually doesn't restrict stages.

## Region restriction

Commands may target only the AWS regions you list, such as `eu-west-1`, `eu-central-1`. The rule compares the stack's
region. It doesn't cover global AWS services such as CloudFront, IAM and Route 53, and it doesn't stop anyone from
using AWS directly. For a data residency
requirement, also restrict regions with an AWS Organizations service control policy.

## Command restriction

The commands you list don't run for anyone in the organization. You can block `deploy`, `delete`, `dev`, `rollback`,
`stack recover`, `script run` and `deployment-script run`. `diff` and `validate` always run, so developers can still
check a config.

Blocking `delete` stops only deletes through Stacktape. To stop a stack from being deleted by any tool, use
[Protect stacks from deletion](/guardrails/security-and-data-protection#protect-stacks-from-deletion), which turns on
CloudFormation termination protection.

## Require custom domains

Every web service and hosting bucket must set `customDomains`, so users reach them on your domain instead of an
address AWS or Stacktape generated. See [Custom domains](/resources/networking/custom-domains) for setting them up.
