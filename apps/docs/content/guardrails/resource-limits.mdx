# Resource limit guardrails

These guardrails set upper limits on sizes, under **Resource limits** on **Security → Guardrails**. They stop mistakes,
such as 10 GB of memory where 1 GB was meant, not spending; for spend, set a [budget](/managing-costs/budgets).
[Guardrails overview](/guardrails/overview) explains who they bind and how to set them up.

## Function memory limit

Every function's `memory` must be at or under the maximum (128 to 10,240 MB). The check covers
[Lambda functions](/resources/compute/lambda-function) and [edge functions](/resources/compute/edge-function).
A function that doesn't set `memory` counts as 1,024 MB, so a limit below that blocks functions on their defaults.

```text
Blocked by the organization guardrail "Function memory limit". Function `imageResizer` uses `3008 MB`, exceeding the
`2048 MB` limit.
```

Most functions run well between 256 and 2,048 MB. A ceiling of 2,048 or 3,008 MB catches typos and leaves room for
memory-heavy work such as image processing.

## Function timeout limit

Every function's `timeout` must be at or under the maximum (1 to 900 seconds), for Lambda and edge functions. A function
that doesn't set `timeout` counts as 20 seconds.

A long timeout often means the work belongs in a [worker service](/resources/compute/worker-service) or a
[batch job](/resources/compute/batch-job). A limit of 30 to 60 seconds covers most APIs and event handlers.

## Container resource limit

Every container workload's `resources.cpu` and `resources.memory` must be at or under the maximums you set. It covers
web, private and worker services and multi-container workloads. Set one value to cap only that one. A workload that
doesn't set `cpu` or `memory`, such as one that runs on EC2 instance types, isn't checked for that value.

## Stacktape resource count limit

A config may declare at most so many resources (1 to 10,000). Each resource in your config counts once, however many
AWS resources it creates. Use it to keep stacks small enough to understand; CloudFormation's own limit of 500 resources
per stack is counted separately, by AWS.

To forbid whole resource types, such as OpenSearch, use [Blocked resource types](/guardrails/databases#blocked-resource-types).
