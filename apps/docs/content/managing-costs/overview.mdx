# Costs overview

AWS bills your AWS account for everything your stacks run, as it would without Stacktape. Stacktape adds no markup to that bill. If you use the Console, its fee is a separate invoice; see [Billing and subscription](/stacktape-console/billing-and-subscription).

## Estimate before you deploy

[`stacktape init`](/cli/init) prices the setup it proposes: its Review step shows the monthly price of each resource and the total, for the region you pick. `stacktape init --headless` prints the same estimate in the terminal. Both also write a config file; in a project that already has one, init writes `stacktape.generated.yml` beside it and leaves yours alone.

Init doesn't price changes you make to your config later. For those, add up the pricing notes on the resource pages, or use the [AWS Pricing Calculator](https://calculator.aws/). For example, a [worker service](/resources/compute/worker-service) with 0.5 vCPU and 1 GB adds about $18 a month on x86 Fargate in us-east-1, whether or not it has work.

What makes a bill large is mostly what runs all the time:

- **Always-on resources** bill by the hour, even with no traffic: web, private and worker services, multi-container workloads, relational databases, Redis, OpenSearch, load balancers, Kafka clusters and bastion hosts. They set your baseline.
- **Pay-per-use resources** bill per request, message or GB stored: Lambda functions, HTTP API Gateways, DynamoDB on demand, SQS, SNS and S3. With little traffic they cost close to nothing, but stored data still costs money.
- **Every stage is a full copy.** A `staging` stage costs about as much as `production` with the same sizes. A pull request preview that lives for three days costs about three days of its always-on resources. Delete stages you no longer use with [`stacktape delete`](/cli/delete).
- **Git deployments on your own runner** add the runner's EC2 instance while it builds and its disk while it waits. See [Build runners](/ci-cd-and-gitops/build-runners).

Each resource page has a pricing note, and the [resource catalog](/resources#what-resources-cost) marks which resources cost money while idle.

## After you deploy

The Console shows your AWS spend per project, stage and resource from the cost reports of your connected AWS accounts. Cost data needs the Console and a connected account; reports arrive about a day after the costs occur. See [Cost dashboards](/managing-costs/dashboards).

Without the Console, use AWS Cost Explorer. Every Stacktape stack carries the tags `stp:project-name`, `stp:stage` and `stp:stack-name`, which AWS copies to the resources that support tags. [Activate them as cost allocation tags](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/activating-tags.html) to group your costs by project and stage.

To hear about spend before the invoice, create a [budget](/managing-costs/budgets) for each AWS account you deploy to. A budget alerts you; it never stops anything. To prevent expensive deploys, such as oversized instances, use [resource limit guardrails](/guardrails/resource-limits).

## Costs FAQ

### How fresh is the cost data?

AWS delivers cost reports a few times a day. A new stack appears about a day after its first deploy, and a newly connected account has its first numbers about a day after you connect it. The Costs page says when the report was last updated.

### Can a budget watch a single project or stage?

No. Each budget watches one whole AWS account. To track production and development separately, deploy them to separate AWS accounts and give each one a budget. To see spend per project and stage, use the [Costs page](/managing-costs/dashboards).
