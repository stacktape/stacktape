A `cloudwatch-alarm` event runs a [Lambda function](/resources/compute/lambda-function) when one of your
[alarms](/observability/alarms) goes into the `ALARM` state. Use it when the response needs code: restart something,
open a ticket, page an on-call tool the alarm can't notify directly.

If a person only needs to see the alert, skip the function and add `notificationChannels` to the alarm. Alarms notify
Slack, Microsoft Teams, email, Discord and webhooks without code; see [alert channels](/observability/alert-channels).

## Basic example

The alarm lives on the resource it watches. The trigger names it by the resource's name, `alarms` and the alarm's
position in that list:

<CodeBlock
  intellisense
  tabs={[
    {
      label: 'TypeScript',
      lang: 'typescript',
      code: `import { defineConfig, LambdaFunction, JsBundleLambdaPackaging } from 'stacktape';

// [!code focus-start]
export default defineConfig(() => {
  const api = new LambdaFunction({
    packaging: new JsBundleLambdaPackaging({ entryfilePath: './src/api.ts' }),
    alarms: [
      {
        description: 'API error rate above 5%',
        trigger: { type: 'lambda-error-rate', properties: { thresholdPercent: 5 } }
      }
    ]
  });

  const onApiErrors = new LambdaFunction({
    packaging: new JsBundleLambdaPackaging({ entryfilePath: './src/on-api-errors.ts' }),
    events: [
      {
        type: 'cloudwatch-alarm',
        properties: { alarmName: 'api.alarms.0' }
      }
    ]
  });

  return {
    resources: { api, onApiErrors }
  };
});
// [!code focus-end]`
    }
  ]}
/>

`api.alarms.0` is the first alarm in the `alarms` list of the `api` resource. An alarm that you defined in the Console
for a resource is `<resource>.alarms.<alarm name>`. The alarm must be in the same stack.

Several functions can reference the same alarm. Each one gets its own EventBridge rule and runs independently.

## Handling the event

The function receives the CloudWatch "Alarm State Change" event from EventBridge. It runs only when the alarm moves
into `ALARM`, not when it recovers.

```typescript
type AlarmEvent = {
  detail: {
    alarmName: string;
    state: { value: string; reason: string; timestamp: string };
    previousState: { value: string };
  };
};

export default async (event: AlarmEvent) => {
  const { alarmName, state } = event.detail;
  console.info(`${alarmName} is ${state.value}: ${state.reason}`);
  // remediation or paging logic
};
```

The [AWS event reference](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/cloudwatch-and-eventbridge.html)
lists every field.

The event arrives asynchronously. If the function throws, Lambda retries it twice, so make side effects idempotent: an
alarm that pages twice for one incident is noise. To keep events that still fail, set
[`destinations.onFailure`](/resources/compute/lambda-function#api-ref_lambda-function-props--destinations) on the
function.

## Alarm types

The referenced alarm can use any trigger type its resource supports:

| Resource | Alarm trigger types |
|---|---|
| [Lambda function](/resources/compute/lambda-function) | `lambda-error-rate`, `lambda-duration` |
| [Relational database](/resources/databases/relational-database) | `database-read-latency`, `database-write-latency`, `database-cpu-utilization`, `database-free-storage`, `database-free-memory`, `database-connection-count` |
| [HTTP API Gateway](/resources/networking/http-api-gateway) | `http-api-gateway-error-rate`, `http-api-gateway-latency` |
| [Application Load Balancer](/resources/networking/application-load-balancer) | `application-load-balancer-error-rate`, `application-load-balancer-unhealthy-targets`, `application-load-balancer-custom` |
| [SQS queue](/resources/messaging/sqs-queue) | `sqs-queue-received-messages-count`, `sqs-queue-not-empty` |

Thresholds, evaluation windows and notifications are covered in [Alarms](/observability/alarms).

## Limits

- Only Lambda functions accept `cloudwatch-alarm` events.
- `alarmName` is the only property. You can't reshape the event or reference an alarm in another stack or account.
  For those, send the alarm's events to an [event bus](/resources/messaging/event-bus) and use an
  [event bus trigger](/resources/triggers/event-bus-events).
- Dev mode doesn't create alarms, so the trigger doesn't fire in a dev stack.
