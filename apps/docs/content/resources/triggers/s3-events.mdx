An `s3` event runs a [Lambda function](/resources/compute/lambda-function) or a
[batch job](/resources/compute/batch-job) when objects are created, deleted or restored in an
[S3 bucket](/resources/storage/s3-bucket). Use it to process files as they arrive: resize images, import CSV files,
scan uploads.

To process uploads in batches or at a controlled rate, put an [SQS queue](/resources/triggers/sqs-events) between the
bucket and the consumer.

## Basic example

This function runs for every object uploaded under `uploads/`:

<CodeBlock
  intellisense
  tabs={[
    {
      label: 'TypeScript',
      lang: 'typescript',
      code: `import {
  defineConfig,
  Bucket,
  LambdaFunction,
  S3Integration,
  $ResourceParam,
  JsBundleLambdaPackaging
} from 'stacktape';

// [!code focus-start]
export default defineConfig(() => {
  const imagesBucket = new Bucket({});

  const processImage = new LambdaFunction({
    packaging: new JsBundleLambdaPackaging({
      entryfilePath: './src/process-image.ts'
    }),
    memory: 1024,
    timeout: 60,
    connectTo: [imagesBucket],
    events: [
      new S3Integration({
        bucketArn: $ResourceParam('imagesBucket', 'arn'),
        s3EventType: 's3:ObjectCreated:*',
        filterRule: {
          prefix: 'uploads/'
        }
      })
    ]
  });

  return {
    resources: { imagesBucket, processImage }
  };
});
// [!code focus-end]
`
    }
  ]}
/>

`bucketArn` takes the bucket's ARN: `$ResourceParam('imagesBucket', 'arn')` for a bucket in the stack, or an ARN string
for another bucket. The trigger doesn't give the function access to the objects; `connectTo` does that. See
[Connecting resources](/configuration/connecting-resources).

The function receives the standard S3 notification event. Object keys arrive URL-encoded: spaces are `+` and other
characters are percent-encoded. Decode the key before you read the object:

```typescript
export default async (event: {
  Records: Array<{ eventName: string; s3: { bucket: { name: string }; object: { key: string; size: number } } }>;
}) => {
  for (const record of event.Records) {
    const key = decodeURIComponent(record.s3.object.key.replace(/\+/g, ' '));
    console.info(record.eventName, record.s3.bucket.name, key);
  }
};
```

After `stacktape deploy`, upload a file and read the function's logs:

```bash
aws s3 cp ./photo.jpg s3://<bucket-name>/uploads/photo.jpg
```

```bash
stacktape logs processImage --stage dev
```

`stacktape param get imagesBucket name --stage dev --region eu-west-1` prints the bucket name.

## Event types

`s3EventType` picks the operation. `s3:ObjectCreated:*` covers every way an object is created and is the right choice
for most uploads.

| Event type | Fires when |
|---|---|
| `s3:ObjectCreated:*` | An object is created in any way |
| `s3:ObjectCreated:Put`, `:Post`, `:Copy`, `:CompleteMultipartUpload` | An object is created in that specific way |
| `s3:ObjectRemoved:*` | An object is deleted |
| `s3:ObjectRemoved:Delete` | An object is permanently deleted |
| `s3:ObjectRemoved:DeleteMarkerCreated` | A versioned object gets a delete marker |
| `s3:ObjectRestore:*`, `:Post`, `:Completed` | A Glacier restore starts or finishes |
| `s3:Replication:*` and its four `Operation…` types | A replication event happens |
| `s3:ReducedRedundancyLostObject` | A Reduced Redundancy object is lost |

## Filter by key

`filterRule` takes a `prefix`, a `suffix` or both. With both, the key must match both:

```typescript
new S3Integration({
  bucketArn: $ResourceParam('dataBucket', 'arn'),
  s3EventType: 's3:ObjectCreated:*',
  filterRule: { prefix: 'imports/', suffix: '.csv' }
})
```

S3 filters only on the key. To skip objects by size or content type, check them at the start of the handler.

Several functions can react to the same bucket if their filters don't overlap: S3 rejects two notifications for the
same event type whose prefix and suffix can match the same key. When several consumers need every event, set
`enableEventBusNotifications: true` on the bucket and give each one an
[event bus trigger](/resources/triggers/event-bus-events) on the default bus with `source: ['aws.s3']`.

## Avoid loops

If the function writes its output to the same bucket and the trigger matches that output, every write runs the
function again. The loop can run thousands of invocations per second and costs money until you stop it.

- Write output to a different bucket. This is the safest option.
- Or read from one prefix and write to another: trigger on `uploads/`, write to `processed/`.
- Or filter on the suffix: trigger on `.jpg`, write `.webp`.

If a loop is already running, remove the trigger and deploy, or set the function's reserved concurrency to 0 in the
AWS console.

## Failures and retries

S3 invokes the function asynchronously. If the function throws, Lambda retries it twice and then drops the event. To
keep events that still fail, set
[`destinations.onFailure`](/resources/compute/lambda-function#api-ref_lambda-function-props--destinations) on the
function. S3 can deliver the same event more than once, so make the handler idempotent: processing the same file twice
should give the same result.
