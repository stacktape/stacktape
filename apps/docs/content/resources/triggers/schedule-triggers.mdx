A `schedule` event runs a [Lambda function](/resources/compute/lambda-function) or a
[batch job](/resources/compute/batch-job) at fixed times or intervals: nightly cleanup, hourly syncs, weekday reports.
A scheduled function costs nothing between runs, unlike a container that runs a cron daemon all day.

The shortest interval is one minute. Schedules are AWS EventBridge rules, and cron times are in UTC.

## Basic example

<CodeBlock
  intellisense
  tabs={[
    {
      label: 'TypeScript',
      lang: 'typescript',
      code: `import {
  defineConfig,
  LambdaFunction,
  ScheduleIntegration,
  JsBundleLambdaPackaging
} from 'stacktape';

// [!code focus-start]
export default defineConfig(() => {
  const dailyCleanup = new LambdaFunction({
    packaging: new JsBundleLambdaPackaging({
      entryfilePath: './src/cleanup.ts'
    }),
    timeout: 300,
    events: [
      new ScheduleIntegration({
        scheduleRate: 'rate(1 day)'
      })
    ]
  });

  return {
    resources: { dailyCleanup }
  };
});
// [!code focus-end]
`
    }
  ]}
/>

The function runs once a day, counted from the deploy. Its logs show each run:

```bash
stacktape logs dailyCleanup --stage dev
```

To run it once without waiting, invoke it from the AWS console or with `aws lambda invoke`.

## Rate expressions

`rate(<value> <unit>)` runs at a fixed interval. The unit is `minute`, `hour` or `day`, plural for values above 1.

| Expression | Runs |
|---|---|
| `rate(1 minute)` | Every minute |
| `rate(5 minutes)` | Every 5 minutes |
| `rate(12 hours)` | Every 12 hours |
| `rate(7 days)` | Once a week |

## Cron expressions

`cron(...)` runs at set times. AWS uses six fields, not the five of Unix cron, and all times are UTC:

```text
cron(minutes hours day-of-month month day-of-week year)
```

One of the two day fields must be `?`. You can't use `*` in both.

| Expression | Runs |
|---|---|
| `cron(0 9 * * ? *)` | Every day at 9:00 UTC |
| `cron(0 18 ? * MON-FRI *)` | Weekdays at 18:00 UTC |
| `cron(0 0 1 * ? *)` | The first day of each month at midnight UTC |
| `cron(0/15 * * * ? *)` | Every 15 minutes |
| `cron(0 12 ? * 2#1 *)` | The first Monday of each month at noon UTC |

Cron doesn't follow daylight saving time. A job at 9:00 New York time needs `cron(0 14 …)` in winter and `cron(0 13 …)`
in summer, or a check of the local time in your code. The
[AWS reference](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-scheduled-rule-pattern.html) lists every
wildcard.

## Custom payloads

By default the function receives EventBridge's scheduled event, with fields such as `time` and `resources`. Set one of
these to send something else:

- `input`: a fixed JSON value.
- `inputPath`: a JSONPath into the event, for example `'$.time'`.
- `inputTransformer`: values picked from the event (`inputPathsMap`) placed into your own template (`inputTemplate`).

Use only one of them per schedule. `input` is the common case: one function with two schedules that tell it what to
do.

<CodeBlock
  intellisense
  tabs={[
    {
      label: 'TypeScript',
      lang: 'typescript',
      code: `import {
  defineConfig,
  LambdaFunction,
  ScheduleIntegration,
  JsBundleLambdaPackaging
} from 'stacktape';

export default defineConfig(() => {
  const syncJob = new LambdaFunction({
    packaging: new JsBundleLambdaPackaging({
      entryfilePath: './src/sync.ts'
    }),
    timeout: 300,
    // [!code focus-start]
    events: [
      new ScheduleIntegration({
        scheduleRate: 'rate(5 minutes)',
        input: { mode: 'incremental' }
      }),
      new ScheduleIntegration({
        scheduleRate: 'cron(0 3 * * ? *)',
        input: { mode: 'full' }
      })
    ]
    // [!code focus-end]
  });

  return {
    resources: { syncJob }
  };
});
`
    }
  ]}
/>

The handler gets exactly the `input` value as its event:

```typescript
export default async (event: { mode: 'incremental' | 'full' }) => {
  console.info(`Running ${event.mode} sync`);
};
```

An `inputTransformer` that adds the run time to a fixed message:

```typescript
new ScheduleIntegration({
  scheduleRate: 'rate(1 hour)',
  inputTransformer: {
    inputPathsMap: { eventTime: '$.time' },
    inputTemplate: { message: 'Scheduled run at <eventTime>' }
  }
})
```

## Pause a schedule

Set `enabled: false` and deploy. The rule stays in the stack with its expression and payload. Setting it back to `true`
(the default) resumes it at the next scheduled time.

## Failures and overlapping runs

EventBridge invokes the function asynchronously. If the function throws, Lambda retries it twice. A scheduled job that
fails quietly is easy to miss, so add a `lambda-error-rate` [alarm](/observability/alarms) to the function.

If a run is still going when the next one is due, the next one starts anyway, in parallel. Make the job safe to overlap,
or take a lock (for example a conditional write to DynamoDB) at the start.
