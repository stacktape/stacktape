A private service runs always-on containers that only other resources in your stack can call, such as an internal
API or a gRPC backend. It runs on ECS (Fargate by default, or EC2), has no public endpoint, and Stacktape handles
service discovery and scaling. Add a [health check](#health-checks) so ECS replaces a container that runs but stops
answering.

At least one container runs and bills all the time: 0.25 vCPU and 512 MB cost about $9 a month on x86 Fargate in
us-east-1 ([Fargate pricing](https://aws.amazon.com/fargate/pricing/)). For a container with a public URL, use a
[web service](/resources/compute/web-service); for one nothing calls, such as a queue consumer, a
[worker service](/resources/compute/worker-service).

## Basic example

<CodeBlock
  intellisense
  tabs={[
    {
      label: 'TypeScript',
      lang: 'typescript',
      code: `import { defineConfig, PrivateService, JsBundleImagePackaging } from 'stacktape';

// [!code focus-start]
export default defineConfig(() => {
  const internalApi = new PrivateService({
    packaging: new JsBundleImagePackaging({
      entryfilePath: './src/internal-api.ts'
    }),
    resources: {
      cpu: 0.25,
      memory: 512
    }
  });

  return {
    resources: { internalApi }
  };
});
// [!code focus-end]`
    }
  ]}
/>

The service listens on port 3000 unless you set `port`; Stacktape passes the port to your code as the `PORT` variable.
Resources that call it list it in `connectTo` and get its address; see
[Connecting to other resources](#connecting-to-other-resources).

## Compute resources

Fargate (default) runs containers without servers to manage. EC2 runs them on instances Stacktape manages.

### Fargate

Set `cpu` (0.25 to 16 vCPU) and a `memory` that fits it; the [configuration reference](#configuration-reference)
lists the combinations. `architecture: 'arm64'` runs on Graviton, about 20% cheaper than the default `x86_64`.

<CodeBlock
  intellisense
  tabs={[

      cpu: 1,

`

Set `instanceTypes` instead of `cpu` and `memory`, for example `t3.medium` or the Graviton `c6g.large`. Start with
Fargate and switch only for a concrete cost or capability reason.

## Scaling

The service runs `minInstances` containers at all times and adds more, up to `maxInstances`, when average CPU or
memory use passes its target. Requests are spread across all running containers.

<CodeBlock
  intellisense
  tabs={[
    {
      label: 'TypeScript',
      lang: 'typescript',
      code: `import { defineConfig, PrivateService, JsBundleImagePackaging } from 'stacktape';

export default defineConfig(() => {
  const internalApi = new PrivateService({
    packaging: new JsBundleImagePackaging({
      entryfilePath: './src/internal-api.ts'
    }),
    resources: { cpu: 0.5, memory: 1024 },
    // [!code focus-start]
    scaling: {
      minInstances: 2,
      maxInstances: 10,
      scalingPolicy: {
        keepAvgCpuUtilizationUnder: 70,
        keepAvgMemoryUtilizationUnder: 80
      }
    }
    // [!code focus-end]
  });

  return { resources: { internalApi } };
});
`
    }
  ]}
/>

With the same `minInstances` and `maxInstances`, the service doesn't scale.

## Load balancing

Two modes decide who can reach the service:

| | `service-connect` (default) | `application-load-balancer` |
|---|---|---|
| Who can call it | Container workloads in the stack | Anything in the VPC, including VPC Lambda functions and a bastion |
| Cost | The stack's service discovery namespace, about $0.50 a month for all services | About $16 a month plus capacity units |

Keep `service-connect` unless something other than a container must call the service.

### Using Service Connect

<CodeBlock
  intellisense
  tabs={[
    {
      label: 'TypeScript',
      lang: 'typescript',
      code: `import { defineConfig, PrivateService, JsBundleImagePackaging } from 'stacktape';

export default defineConfig(() => {
  const internalApi = new PrivateService({
    packaging: new JsBundleImagePackaging({
      entryfilePath: './src/internal-api.ts'
    }),
    resources: { cpu: 0.25, memory: 512 },
    // [!code focus-start]
    loadBalancing: {
      type: 'service-connect'
    }
    // [!code focus-end]
  });

  return { resources: { internalApi } };
});
`
    }
  ]}
/>

Callers that list the service in `connectTo` get its address in `STP_<NAME>_ADDRESS`.

### Using an Application Load Balancer

<CodeBlock
  intellisense
  tabs={[
    {
      label: 'TypeScript',
      lang: 'typescript',
      code: `import { defineConfig, PrivateService, JsBundleImagePackaging } from 'stacktape';

export default defineConfig(() => {
  const internalApi = new PrivateService({
    packaging: new JsBundleImagePackaging({
      entryfilePath: './src/internal-api.ts'
    }),
    resources: { cpu: 0.5, memory: 1024 },
    // [!code focus-start]
    loadBalancing: {
      type: 'application-load-balancer'
    }
    // [!code focus-end]
  });

  return { resources: { internalApi } };
});
`
    }
  ]}
/>

The service gets an internal load balancer with a stable DNS name in the VPC. `connectTo` injects the same
`STP_<NAME>_ADDRESS` variable.

This mode needs the [Stacktape Console](/getting-started/add-the-console) for now: without an account, the deploy stops
because the CLI expects the Console's default domain for every load balancer without its own domain or certificate, and
this one can't have either. Without an account, keep `service-connect`.

## Packaging

Pick how the image is built:

| Type | Use it for |
|---|---|
| [`js-bundle`](/packaging/containers/js-bundle) | JavaScript or TypeScript with one entry file. Stacktape bundles it into a small image. |
| [`buildpack`](/packaging/containers/buildpack) | Other languages without a Dockerfile: Python, Go, Rust, Java, PHP, Ruby, .NET and more |
| [`dockerfile`](/packaging/containers/dockerfile) | Your own Dockerfile |
| [`prebuilt-image`](/packaging/containers/prebuilt-image) | An image another pipeline already built |

## Connecting to other resources

`connectTo` works both ways: the service uses it to reach other resources, and callers use it to reach the service.
Here the private service reads a bucket, and a public web service calls the private service:

<CodeBlock
  intellisense
  tabs={[
    {
      label: 'TypeScript',
      lang: 'typescript',
      code: `import {
  defineConfig,
  PrivateService,
  WebService,
  Bucket,
  JsBundleImagePackaging
} from 'stacktape';

// [!code focus-start]
export default defineConfig(() => {
  const dataBucket = new Bucket({});

  const internalApi = new PrivateService({
    packaging: new JsBundleImagePackaging({
      entryfilePath: './src/internal-api.ts'
    }),
    resources: { cpu: 0.25, memory: 512 },
    connectTo: [dataBucket]
  });

  const publicApi = new WebService({
    packaging: new JsBundleImagePackaging({
      entryfilePath: './src/public-api.ts'
    }),
    resources: { cpu: 0.25, memory: 512 },
    connectTo: [internalApi]
  });

  return { resources: { dataBucket, internalApi, publicApi } };
});
// [!code focus-end]
`
    }
  ]}
/>

`internalApi` gets `STP_DATA_BUCKET_NAME` and `STP_DATA_BUCKET_ARN`. `publicApi` gets `STP_INTERNAL_API_ADDRESS`, a
`host:port` without a scheme: call `http://${process.env.STP_INTERNAL_API_ADDRESS}` over HTTP, or pass it as it is to a
gRPC client. In a config value, build the URL with `$CfFormat('http://{}', $ResourceParam('internalApi', 'address'))`.
For AWS services `connectTo` doesn't cover, add `iamRoleStatements`.

## Health checks

`internalHealthCheck` runs a command inside the container at an interval and replaces the container after `retries`
failures in a row. It catches a process that runs but no longer answers.

<CodeBlock
  intellisense
  tabs={[
    {
      label: 'TypeScript',
      lang: 'typescript',
      code: `import { defineConfig, PrivateService, JsBundleImagePackaging } from 'stacktape';

export default defineConfig(() => {
  const internalApi = new PrivateService({
    packaging: new JsBundleImagePackaging({
      entryfilePath: './src/internal-api.ts'
    }),
    resources: { cpu: 0.25, memory: 512 },
    // [!code focus-start]
    internalHealthCheck: {
      healthCheckCommand: ['CMD-SHELL', 'curl -f http://localhost:3000/health || exit 1'],
      intervalSeconds: 30,
      timeoutSeconds: 5,
      retries: 3,
      startPeriodSeconds: 60
    }
    // [!code focus-end]
  });

  return { resources: { internalApi } };
});
`
    }
  ]}
/>

`startPeriodSeconds` is a grace period after start; set it to your service's start time. With an Application Load
Balancer, the load balancer also runs its own HTTP checks against the containers, which you can tune with
[overrides](/configuration/overrides-and-escape-hatches).

## Side containers

Side containers run in the same task as the service and share its CPU and memory.

### Using run-on-init sidecars

A `run-on-init` container runs before the service starts, for example for migrations. It must exit with code 0, or
the task stops.

<CodeBlock
  intellisense
  tabs={[
    {
      label: 'TypeScript',
      lang: 'typescript',
      code: `import { defineConfig, PrivateService, JsBundleImagePackaging } from 'stacktape';

export default defineConfig(() => {
  const internalApi = new PrivateService({
    packaging: new JsBundleImagePackaging({
      entryfilePath: './src/internal-api.ts'
    }),
    resources: { cpu: 0.5, memory: 1024 },
    // [!code focus-start]
    sideContainers: [
      {
        name: 'migrate',
        containerType: 'run-on-init',
        packaging: new JsBundleImagePackaging({
          entryfilePath: './src/migrate.ts'
        })
      }
    ]
    // [!code focus-end]
  });

  return { resources: { internalApi } };
});
`
    }
  ]}
/>

### Using always-running sidecars

An `always-running` container runs next to the service for its whole life, for example an OpenTelemetry collector
the service reaches on `localhost`. If it crashes, ECS replaces the whole task, service included.

<CodeBlock
  intellisense
  tabs={[

});
`

## Private subnets and NAT

Containers run in public subnets with a public IP address by default and reach the internet directly.
`usePrivateSubnetsWithNAT: true` moves them to private subnets and sends outbound traffic through NAT, for example
when a partner API allowlists your IP addresses.

The flag requires `stackConfig.nat`, which decides the NAT device, its cost and the outbound IP addresses: one
Stacktape-managed instance (`ec2`, about $7 a month), one per availability zone with failover (`ha-ec2`), or AWS NAT
Gateways (`gateway`, about $32 a month per zone plus $0.045 per GB). See
[VPC and networking](/configuration/connecting-resources#vpc-and-networking).

## Logging

Container output goes to CloudWatch Logs, kept for 90 days by default. Read it with [`stacktape logs`](/cli/logs), or
send it elsewhere with [log forwarding](/observability/log-forwarding).

For a gRPC server, set `port` (for example `50051`) and `protocol: 'grpc'`. `protocol` (`http`, `http2` or `grpc`)
also turns on protocol-specific metrics such as the 5xx error rate.

## Remote sessions

`enableRemoteSessions: true` lets you open a shell in a running container with
[`stacktape container shell`](/cli/container-session). It adds a small Systems Manager agent container.

## EFS storage

A private service mounts an [EFS file system](/resources/storage/efs-filesystem) with `volumeMounts`, the same way as a
[web service](/resources/compute/web-service#efs-storage). `stacktape dev` doesn't mount EFS, so test persistence and
read-only mounts on a deployed stage.
