A `hosting-bucket` hosts a static site: Stacktape builds it, uploads the output to S3 and serves it through a CloudFront
CDN. Use it for single-page apps (React, Vue, Angular, Vite) and for static sites and fully pre-rendered framework
output. You pay for storage, requests and traffic, which for most sites is a few dollars a month or less.

For server rendering, use the framework resource instead: [Next.js](/resources/frontend/nextjs),
[Astro](/resources/frontend/astro), [Nuxt](/resources/frontend/nuxt), [SvelteKit](/resources/frontend/sveltekit),
[SolidStart](/resources/frontend/solidstart), [TanStack Start](/resources/frontend/tanstack-start) or
[Remix](/resources/frontend/remix). For files that aren't a website, use an [S3 bucket](/resources/storage/s3-bucket).

## Basic example

On `stacktape deploy`, Stacktape runs `build.command`, uploads `uploadDirectoryPath` (here `./dist`) and prints the
site's URL, a CloudFront address until you add a custom domain. Open it and reload a client-side route such as `/about`
to check that routing works. `dev.command` is what [`stacktape dev`](/local-development/dev-mode-overview) runs.

## Build

`build.command` runs through the shell, so `npm ci && npm run build` works. `workingDirectory` (relative to the project
root, which is the default) sets where it runs; if that folder has its own `package.json`, Stacktape installs its
dependencies first. Point `uploadDirectoryPath` at the build output, not the sources.

```typescript
new HostingBucket({
  uploadDirectoryPath: './apps/site/dist',
  build: { command: 'npm run build', workingDirectory: './apps/site' },
  dev: { command: 'npm run dev', workingDirectory: './apps/site' }
})
```

Leave out `build` when another CI step already produced the files. `excludeFilesPatterns`, such as
`['**/*.map', '**/.DS_Store']`, keeps files out of the upload. Everything uploaded is public, so never put secrets in
the output folder.

## Caching and routing presets

`hostingContentType` sets browser caching, CDN caching and routing for the kind of site you have:

| Preset | For | What it does |
|--------|-----|--------------|
| `static-website` (default) | Multi-page static sites | CDN caches files; browsers revalidate, so visitors see a new deploy right away |
| `single-page-app` | React, Vue, Angular, Vite and other client-routed apps | Serves `index.html` for client-side routes; caches hashed `.js` and `.css` forever |
| `astro-static-website` | Static Astro builds | Caches hashed `_astro/` assets forever; keeps HTML fresh |
| `sveltekit-static-website` | Static SvelteKit builds | Caches hashed `_app/` assets forever; keeps HTML fresh |
| `nuxt-static-website` | Static Nuxt builds | Caches hashed `_nuxt/` assets forever; keeps HTML fresh |
| `gatsby-static-website` | Gatsby builds | Follows Gatsby's caching recommendations |

`fileOptions` adds headers, such as `Cache-Control`, to files matching an `includePattern` when a preset is close but
not exact.

`indexDocument` (default `/index.html`) is served for `/`, and `errorDocument` for missing pages, for example
`/404.html`. URLs are normalized so `/about` serves `/about.html`; `disableUrlNormalization: true` turns that off.

## Deploy-time values

A static site can't ask your stack for values such as the API URL. `injectEnvironment` puts them into the page: on each
deploy, Stacktape writes them into the uploaded HTML files, where your code reads `window.STP_INJECTED_ENV.API_URL`.
Your build doesn't change.

```typescript
new HostingBucket({
  uploadDirectoryPath: './dist',
  build: { command: 'npm run build' },
  injectEnvironment: { API_URL: $ResourceParam('api', 'url') }
})
```

These values end up in the browser, so use them for public settings, not secrets. `writeDotenvFilesTo` also writes
them to `.env.<stage>` in the given folder after each deploy, merged with what's there, for local scripts and tools.

In dev mode, `stacktape dev` passes the `injectEnvironment` values to the `dev.command` server as environment variables.
A `$ResourceParam` of a function or container resolves to the URL dev mode runs it at. The values are also written to
`.env.local` in the dev `workingDirectory`, inside a block between `# >>> stacktape dev` and `# <<< stacktape dev <<<`
lines; your own lines in that file stay. Bundlers expose only prefixed variables to browser code, so name them
accordingly, for example `VITE_API_URL`, and read `import.meta.env.VITE_API_URL`.

## Custom domain

```typescript
new HostingBucket({
  uploadDirectoryPath: './dist',
  customDomains: [{ domainName: 'www.example.com' }]
})
```

Set the domain up once before the first deploy that uses it: run `stacktape domain add --region <your region>` for the
root domain, point your registrar at the Route 53 hosted zone it creates, and run it again until the certificates are
issued. The CDN needs a certificate in `us-east-1`, which the command requests too. Without an issued certificate, the
deploy stops with an error. Stacktape then creates the DNS record and renews the certificate.

To keep DNS at another provider, request an ACM certificate in `us-east-1` yourself, set `customCertificateArn` and
`disableDnsRecordCreation: true`, and point a CNAME at the CloudFront domain. [Custom domains](/resources/networking/custom-domains)
covers both paths.

## API routes on the same domain

`routeRewrites` sends matching paths to another origin, for example `/api/*` to an HTTP API Gateway, so the site and its
API share one domain and need no CORS. Rules are checked in order; anything unmatched goes to the bucket.

```typescript
new HostingBucket({
  uploadDirectoryPath: './dist',
  hostingContentType: 'single-page-app',
  routeRewrites: [{ path: '/api/*', routeTo: { type: 'http-api-gateway', properties: { httpApiGatewayName: 'api' } } }]
})
```

The [CDN](/resources/networking/cdn) page lists all origin types and caching options for rewrites.

## Edge functions and firewall

`edgeFunctions` runs an [edge function](/resources/compute/edge-function) on each request (`onRequest`, before the
cache lookup) or response (`onResponse`), for example for redirects, basic auth or headers. Keep application logic in a
normal backend.

`useFirewall` puts a [web application firewall](/resources/security/web-application-firewall) with `scope: 'cdn'` in
front of the site.
