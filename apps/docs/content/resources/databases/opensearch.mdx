An OpenSearch domain is a managed Amazon OpenSearch Service cluster for full-text search, log analytics and
dashboards. You set the node types, counts and storage; AWS runs the cluster.

It runs all the time. The basic example below, one `t3.medium.search` node with 20 GB, costs about $56 a month in
us-east-1 ([OpenSearch pricing](https://aws.amazon.com/opensearch-service/pricing/)). For key-value lookups, use
[DynamoDB](/resources/databases/dynamodb); for occasional simple text search, PostgreSQL full-text search in a
[relational database](/resources/databases/relational-database) may be enough. In
[dev mode](#dev-mode) it runs locally in Docker at no AWS cost.

This creates a single-node domain for development or low-traffic search. Always set `clusterConfig.instanceType`;
without it, AWS picks its own default, a larger and more expensive instance. `storage.size` is the EBS volume per data
node. Check the domain after the deploy:

```bash
stacktape query opensearch search --operation indices --stage dev
```

## Engine version

`version` defaults to `'2.17'`. Set it explicitly so a future Stacktape release with a newer default doesn't upgrade
your domain. Accepted: `2.17`, `2.15`, `2.13`, `2.11`, `2.9`, `2.7`, `2.5`, `2.3`, `1.3`, `1.2`, `1.1` and `1.0`.

## Cluster configuration

`clusterConfig` sets the data nodes and, optionally, dedicated master and UltraWarm nodes.

### Data nodes

Data nodes hold the indices and answer queries. One `t3.small.search` or `t3.medium.search` node is enough for
development; production clusters usually run memory-optimized nodes such as `r6g.large.search`.

### Dedicated master nodes

Dedicated master nodes manage the cluster state and keep heavy queries from destabilizing it. Add three (an odd count
for quorum) once you have three or more data nodes. They hold no data, so a general-purpose type such as
`m6g.large.search` is enough.

### Warm storage

UltraWarm nodes store rarely read data, such as old logs, for much less than hot storage. Queries on it are slower.

### Production example

Three data nodes, three dedicated masters and Multi-AZ with standby, the setup AWS requires for its 99.99% SLA:

      instanceType: 'r6g.large.search',
      instanceCount: 3,

`iops: 5000` and `throughput: 250` raise the gp3 volumes above their 3,000 IOPS and 125 MiB/s baseline, at extra cost.

### Multi-AZ and standby

With two or more data nodes, Stacktape spreads them across availability zones so the cluster survives a zone outage.
`multiAzDisabled: true` turns that off; don't do it in production.

`standbyEnabled: true` uses three zones with one as standby, which takes over without rebalancing. It needs OpenSearch
1.3 or later, three dedicated masters, three or more data nodes and gp3 or SSD-backed instance types.

## Storage

`storage` sets the EBS volume of each data node. Instance types with local NVMe storage, such as `i3`, don't use it.

| Property | Meaning |
|---|---|
| `size` | GiB per data node, required. The range depends on the instance type. |
| `iops` | gp3 IOPS per data node (default 3000) |
| `throughput` | gp3 throughput per data node in MiB/s (default 125) |

## Networking

`accessibility.accessibilityMode` decides who can reach the domain. Every request must also be signed with AWS
credentials (SigV4) that have access to the domain.

| Mode | Network access |
|---|---|
| `internet` (default) | Public endpoint |
| `vpc` | Resources in the stack's VPC |
| `scoping-workloads-in-vpc` | Only workloads that list the domain in `connectTo` |

Lambda functions need `joinDefaultVpc: true` to reach a domain in a VPC mode.

<Warning>
You can't switch between `internet` and the VPC modes on a deployed domain; it needs a new domain. Pick the mode before
the first deploy, or plan a snapshot and restore.
</Warning>

## Connecting to other resources

Add the domain to a workload's `connectTo`. The workload's role gets access to the domain, and it receives
`STP_SEARCH_DOMAIN_ENDPOINT` (the host name) and `STP_SEARCH_ARN` for a domain named `search`. Sign each request with
the workload's AWS credentials, for example with the OpenSearch JavaScript client:

```ts
import { Client } from '@opensearch-project/opensearch';
import { AwsSigv4Signer } from '@opensearch-project/opensearch/aws';
import { defaultProvider } from '@aws-sdk/credential-provider-node';

const endpoint = process.env.STP_SEARCH_DOMAIN_ENDPOINT!;

// In dev mode the endpoint is a local http:// URL that needs no signing.
const client = endpoint.startsWith('http://')
  ? new Client({ node: endpoint })
  : new Client({
      ...AwsSigv4Signer({ region: process.env.AWS_REGION!, service: 'es', getCredentials: defaultProvider() }),
      node: `https://${endpoint}`
    });
```

## Logging

The domain sends three log types to CloudWatch, each on by default:

| Log type | Contains | Retention |
|---|---|---|
| Error logs | Script errors, invalid queries, indexing and snapshot problems | 30 days |
| Search slow logs | Queries above the thresholds set in your index settings | 5 days |
| Index slow logs | Indexing above the thresholds set in your index settings | 5 days |

Slow logs stay empty until you set thresholds in the index settings, for example
`index.search.slowlog.threshold.query.warn: 2s`. `disabled: true` on a log type skips its log group.

## OpenSearch Dashboards with Cognito

`userPool` names a [user auth pool](/resources/security/user-auth-pool) whose users can sign in to OpenSearch
Dashboards in the browser. Skip it if only your code talks to the domain.

## Dev mode

In [`stacktape dev`](/local-development/dev-mode-overview), the domain runs locally in Docker
(`opensearchproject/opensearch`), and workloads get its local `http://127.0.0.1:<port>` endpoint without
authentication. Run `stacktape dev --remote-resources search` to use the deployed domain instead, for example to test
IAM access.
