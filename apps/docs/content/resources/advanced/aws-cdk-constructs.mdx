An `aws-cdk-construct` adds the resources of an AWS CDK construct to your stack. You write a construct class in
TypeScript or JavaScript, and Stacktape synthesizes it and deploys its resources with the rest of the stack. Use it for
AWS services that have no Stacktape resource, such as Cognito identity pools, IoT rules or MediaConvert, when the CDK's
higher-level constructs save you work.

Check the [resource catalog](/resources/) first; GraphQL APIs, for example, have a native
[AppSync API](/resources/networking/appsync-api) resource. For one or two plain resources,
[raw CloudFormation](/resources/advanced/raw-cloudformation-resources) needs no extra dependencies. To change a resource
Stacktape already creates, use [overrides](/configuration/overrides-and-escape-hatches).

## Basic example

Install the CDK libraries in your project. Stacktape loads them from the `node_modules` next to the construct file:

```bash
npm install aws-cdk-lib constructs
```

```typescript
// cdk/alert-topic.ts
import { Construct } from 'constructs';
import { CfnOutput } from 'aws-cdk-lib';
import * as sns from 'aws-cdk-lib/aws-sns';
import * as subscriptions from 'aws-cdk-lib/aws-sns-subscriptions';

export default class AlertTopic extends Construct {
  constructor(scope: Construct, id: string) {
    super(scope, id);
    const topic = new sns.Topic(this, 'Topic', { displayName: 'Application alerts' });
    topic.addSubscription(new subscriptions.EmailSubscription('ops@example.com'));
    new CfnOutput(this, 'TopicArn', { value: topic.topicArn });
  }
}
```

The file must export a class that extends `Construct`. Stacktape uses the default export; for a named export, set
`exportName` to the class name. A class that extends `Stack` isn't accepted: move its resources into a `Construct`.
Stacktape creates the class twice during a deploy (once to check it), so keep the constructor free of side effects such
as API calls.

The construct's resources get logical IDs that start with the resource name in PascalCase (`AlertsTopic…`), and its
`CfnOutput`s become outputs of the stack.

## Pass values in

`constructProperties` is passed to the constructor as its third argument:

```typescript
new AwsCdkConstruct({
  entryfilePath: './cdk/data-access.ts',
  constructProperties: {
    retentionDays: 14,
    dataBucketArn: $ResourceParam('dataBucket', 'arn')
  }
})
```

```typescript
// cdk/data-access.ts
import { Construct } from 'constructs';
import { Duration } from 'aws-cdk-lib';
import * as iam from 'aws-cdk-lib/aws-iam';
import * as sqs from 'aws-cdk-lib/aws-sqs';

export default class DataAccess extends Construct {
  constructor(scope: Construct, id: string, props: { retentionDays: number; dataBucketArn: string }) {
    super(scope, id);
    new sqs.Queue(this, 'Jobs', { retentionPeriod: Duration.days(props.retentionDays) });
    new iam.ManagedPolicy(this, 'ListData', {
      statements: [new iam.PolicyStatement({ actions: ['s3:ListBucket'], resources: [props.dataBucketArn] })]
    });
  }
}
```

Plain values arrive as they are. A directive such as `$ResourceParam` arrives as its text while the construct runs,
and Stacktape replaces it with the real reference in the finished template. So use it only as a whole property value,
as above. Code that parses or builds on it, such as `Bucket.fromBucketArn()` or `` `${arn}/*` ``, gets the directive
text instead of an ARN.

## Use the construct's resources

A construct can't be a `connectTo` target, and it has no [referenceable parameters](/configuration/referenceable-parameters).
To use one of its resources from a Stacktape resource:

1. Run `stacktape synth --stage dev --region eu-west-1` and find the resource's logical ID in `compiled-template.yaml`.
2. Reference it with [`$CfResourceParam`](/configuration/directives). For the topic in the basic example that is
   `$CfResourceParam('AlertsTopicCF7C81C9', 'TopicArn')`.
3. Grant access with `iamRoleStatements` on the workload.

The CDK keeps a logical ID stable as long as the construct's path doesn't change.

## Limits

- Stacktape deploys the synthesized template only. It doesn't publish CDK assets, so constructs that package local
  files or Docker images, such as `lambda.Code.fromAsset()` or `BucketDeployment`, don't work. Run code with Stacktape
  [Lambda functions](/resources/compute/lambda-function) or containers instead.
- No `overrides` and no dev mode. Change the construct's code instead.
- The construct's resources count toward CloudFormation's 500-resource limit per stack. CDK constructs often create more
  resources than you expect.
