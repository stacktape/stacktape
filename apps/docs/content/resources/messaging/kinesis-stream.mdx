A `kinesis-stream` is an Amazon Kinesis data stream: producers write records, and consumers read them in order per
partition key and can read them again later. Use it for high-volume, ordered data such as clickstreams, telemetry or
change events that several consumers read independently.

A stream costs money while idle. The default on-demand mode charges $0.04 per stream-hour in US East (about $29 for a
30-day month) before any data. For background jobs, an [SQS queue](/resources/messaging/sqs-queue) has no idle charge.
For events that several services react to, an [event bus](/resources/messaging/event-bus) is cheaper at low volume.

export default defineConfig(() => {

  });

  const processor = new LambdaFunction({
    packaging: new JsBundleLambdaPackaging({ entryfilePath: './src/process.ts' }),
    events: [{ type: 'kinesis-stream', properties: { kinesisStreamName: 'clickStream' } }]

  return {
    resources: { clickStream, collector, processor }
  };
});
// [!code focus-end]
`
    }

The stream is on-demand and keeps records for 24 hours. `collector` writes to it; `processor` runs on batches of new
records. Batching, retries and failure handling for consumers are on [Kinesis events](/resources/triggers/kinesis-events).

## Write records

`connectTo` gives a workload permission to read and write the stream and injects its `ARN` and `NAME`. For a stream
named `clickStream`, the variables are `STP_CLICK_STREAM_ARN` and `STP_CLICK_STREAM_NAME`:

```typescript
import { KinesisClient, PutRecordCommand } from '@aws-sdk/client-kinesis';

const kinesis = new KinesisClient({});

await kinesis.send(
  new PutRecordCommand({
    StreamName: process.env.STP_CLICK_STREAM_NAME,
    PartitionKey: 'user-42',
    Data: Buffer.from(JSON.stringify({ userId: '42', page: '/pricing' }))
  })
);
```

Records with the same `PartitionKey` go to the same shard and are read in order. Pick a key with many values, such as
a user or device ID, so the load spreads across shards.

## Capacity mode

|  | On-demand (default) | Provisioned |
|---|---|---|
| Scaling | AWS adds capacity as traffic grows | You set `shardCount` |
| Throughput | Scales with traffic | Per shard: 1 MB/s or 1,000 records/s in, 2 MB/s out |
| Idle cost in US East | $0.04 per stream-hour | $0.015 per shard-hour |
| Traffic cost | Per GB written and read | Per million PUT units ($0.014) |

On-demand needs no planning and suits uneven traffic. For steady traffic, provisioned is cheaper: one shard costs about
$11 a month in US East before PUT units. See [Kinesis pricing](https://aws.amazon.com/kinesis/data-streams/pricing/).

```typescript
new KinesisStream({ capacityMode: 'PROVISIONED', shardCount: 2 })
```

## Retention

Records stay for 24 hours by default. `retentionPeriodHours` keeps them up to 8,760 hours (365 days), so consumers can
reprocess after a bug fix or a new consumer can read history. Retention beyond 24 hours costs extra.

```typescript
new KinesisStream({ retentionPeriodHours: 168 })
```

## Encryption

`encryption: { enabled: true }` encrypts records at rest with the AWS-managed Kinesis key, which needs no extra
permissions. Set `kmsKeyArn` to use your own KMS key. `connectTo` doesn't grant access to that key, so add
`kms:GenerateDataKey` for producers and `kms:Decrypt` for consumers with `iamRoleStatements`.

## Enhanced fan-out

Consumers share each shard's 2 MB/s read throughput. When several consumers read the same stream and latency matters,
give a Lambda consumer its own throughput with `autoCreateConsumer: true` on its
[Kinesis event](/resources/triggers/kinesis-events#enhanced-fan-out). AWS charges per consumer-shard hour and per GB
read.
