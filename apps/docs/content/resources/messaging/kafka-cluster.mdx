A `kafka-cluster` is an Amazon MSK Serverless cluster with IAM authentication in the stack's VPC. There are no broker
sizes, capacity units or network settings to choose; Stacktape sets secure defaults and a dedicated security group. Use
it only when you need Kafka itself, for example for existing Kafka clients or tools.

<Warning>
An MSK Serverless cluster costs about $0.75 per cluster-hour in AWS's US East (Ohio) example, or about $558 for a
31-day month, before partition, data and storage charges. Every stage gets its own cluster. For queues and streams
without Kafka, use an [SQS queue](/resources/messaging/sqs-queue) or a [Kinesis stream](/resources/messaging/kinesis-stream).
</Warning>

## Basic example

```yaml
resources:
  events:
    type: kafka-cluster

  api:
    type: function
    properties:
      packaging:
        type: js-bundle
        properties:
          entryfilePath: src/api.ts
      joinDefaultVpc: true
      connectTo:
        - events
```

`connectTo` injects `ARN`, `NAME` and a comma-separated `BOOTSTRAP_SERVERS` (here `STP_EVENTS_BOOTSTRAP_SERVERS`). It
grants IAM Kafka connect, topic and consumer group actions on this cluster, including `CreateTopic`, but not
`AlterTopic` or `DeleteTopic`.

A Lambda function that connects as a Kafka client needs `joinDefaultVpc: true`. Containers already run in the VPC. To
consume a topic with a Lambda trigger instead, use a [Kafka topic event](/resources/triggers/kafka-topics); its poller
has its own networking and the function doesn't join the VPC.

## Create topics

Topics aren't infrastructure here: MSK Serverless doesn't create them automatically, and CloudFormation can't declare
them for Serverless clusters. Create them with a Kafka admin client, from setup code or a
[deployment script](/resources/advanced/deployment-scripts). For Node.js:

```bash
pnpm add kafkajs aws-msk-iam-sasl-signer-js
```

```ts
import { Kafka } from 'kafkajs';
import { generateAuthToken } from 'aws-msk-iam-sasl-signer-js';

const region = process.env.AWS_REGION!;
const kafka = new Kafka({
  clientId: 'topic-setup',
  brokers: process.env.STP_EVENTS_BOOTSTRAP_SERVERS!.split(','),
  ssl: true,
  sasl: {
    mechanism: 'oauthbearer',
    oauthBearerProvider: async () => ({ value: (await generateAuthToken({ region })).token })
  }
});

const admin = kafka.admin();
await admin.connect();
await admin.createTopics({ topics: [{ topic: 'orders', numPartitions: 3 }] });
await admin.disconnect();
```

`createTopics` skips topics that already exist, so the setup can run on every deploy. Choose the partition count on
purpose: MSK Serverless charges per partition-hour, and partitions also set how many consumers can read in parallel.

## Lambda triggers and VPC endpoints

A [Kafka topic event](/resources/triggers/kafka-topics) on a cluster in the stack makes Stacktape create Lambda and STS
interface endpoints in the VPC for Lambda's poller. They add hourly and per-GB charges in every availability zone.

## Dev mode

Stacktape doesn't emulate Kafka locally, and `stacktape dev` doesn't deploy the cluster unless you ask for it:

```yaml
events:
  type: kafka-cluster
  properties:
    dev:
      remote: true
```

`--remote-resources events` does the same for one session. Either way the real cluster is deployed and billed.
Containers running on your machine can't reach the private cluster by themselves; use a deployed workload or set up
private access to the VPC.

## Regions and deletion

Stacktape checks that MSK Serverless is available before deploying. Supported regions: US East (N. Virginia and Ohio),
US West (Oregon), Canada (Central), Mumbai, Singapore, Sydney, Tokyo, Seoul, Frankfurt, Stockholm, Ireland, London and
Paris. Other regions fail with the list of valid ones.

Deleting the stage deletes the cluster and all topic data; Stacktape doesn't keep it, because a forgotten cluster costs
around $558 a month. Back up or replicate data before you delete.

Every property of an MSK Serverless cluster requires a replacement, and AWS needs a fixed cluster name, so a
replacement may delete the old cluster before creating the new one. Stacktape's change preview marks this as
destructive. To keep it from happening by accident, the resource has no capacity, network, authentication, tag or
override settings.

In a reused VPC, Stacktape picks one public subnet per supported availability zone and needs at least two. MSK doesn't
support the `use1-az3` zone, and zone names map to physical zones differently in each account. So in `us-east-1` the
cluster requires `stackConfig.vpc.reuseVpc`, and Stacktape leaves out `use1-az3` when it picks subnets. In other regions
Stacktape can create the VPC itself.

Prices: [Amazon MSK pricing](https://aws.amazon.com/msk/pricing/) and
[AWS PrivateLink pricing](https://aws.amazon.com/privatelink/pricing/).
